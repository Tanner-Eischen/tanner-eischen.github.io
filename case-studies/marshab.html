The problem

Terrain scores and routes are misleading when gradients use the wrong units, missing cells receive neutral scores, or path heuristics and exports use inconsistent coordinates.

My contribution

I repaired terrain calculations, common validity masks, Mars coordinate handling and A* routing, then added analytical fixtures, independent shortest-path comparisons, provenance manifests and a same-origin React/FastAPI application.

How it works

  1. Checksum-pinned NASA/USGS CTX DEM
  2. 20 m metric grid + common validity mask
  3. Terrain-only suitability + bounded routing
  4. GeoTIFF / Mars-coordinate GeoJSON / provenance

Decisions that shaped the release

  • Use local metric coordinates for the Jezero comparison and spherical Mars distances for global routing. Do not silently mix MOLA and CTX datums.
  • Keep suitability weights and terrain route penalties explicit. The score is relative to the region; route cost is a heuristic distance-equivalent, not rover energy.
  • Preserve every route pixel and forbid diagonal corner cutting. Return explicit coverage and no-path failures rather than fabricated coordinates.

Measured results

The new independent checker reconstructed all 2,359,894 directed edges and matched each of the three archived route costs to Dijkstra within the declared float32-artifact tolerance. This establishes optimality on the serialized graph, not physical mobility. The reference was checked in place rather than regenerated, and the updated checker was not retested inside the earlier container budget.

Archived Jezero CTX reference artifact, verified by its original output checksums. Its manifest records an earlier dirty source revision; the reviewed current revision is identified separately in the evidence download. The patched 0.1.1 local release separately passed a new server calculation and artifact-download checks under its 1 GiB profile; no deployment is implied.

Limits and next questions

  • Terrain-only illustrative candidate cells. No habitat safety, soil strength, ice, dust, solar power, mission economics or rover-energy validation is claimed.
  • Global MOLA cells are about 3.7 km at the equator; they cannot resolve local hazards. CTX is used only within available detailed coverage.
  • GeoJSON coordinates describe Mars and require a planetary-aware viewer; they are not Earth RFC 7946 WGS84 coordinates.
  • Actual Chromium checks verified map/keyboard routing, CTX and MOLA source labels, WebGL camera controls, route downloads, stale-response rejection and useful WebGL fallback. Live availability is time-specific.
  • Implementation is public. This case study includes measured artifacts and metadata. Scientific artifact provenance is retained alongside the source.
  • The final local Docker journey completed at 512 MiB / 0.1 CPU, including a full comparison recompute, without OOM. It reached the memory cap and reclaimed cache; this is no general capacity or headroom guarantee.
  • The live release backend fingerprint and both source checksums matched. Public CTX/MOLA routing, keyboard entry, WebGL orbit/reset and the route download passed. The free service can sleep; availability is time-specific.
