The problem

A stock price could be accepted as evidence for a portfolio total. The evaluation catalog also contained assertion-free cases, so a green result did not always demonstrate a checked answer.

My contribution

I connected typed portfolio tools, scoped numerical verification, explicit answer outcomes, persistent local sessions, and a credential-free synthetic deployment. Evaluation controls exercise the actual verification pipeline.

How it works

  1. Typed tool results
  2. Scoped statement checks
  3. Citations + field expectations
  4. Verified / review / rejected / error

Decisions that shaped the release

  • Verification checks entity, metric, currency/unit, period, source and freshness. Unsupported language requires review.
  • Catalog assertions are validated separately from executed controls. A 75-case catalog is not presented as 75 model runs.
  • Confidence and verification remain distinct. Provider timeouts and incomplete evidence cannot become verified answers.

Measured results

All 75 catalog cases contain assertions. The measured 11 controls use fixed synthetic tool outputs and zero model calls.

A failure worth inspecting

A plausible $180 answer is contradicted by the correct field.

The source contains both amounts. Field-scoped checking rejects the claimed total even though $180 is a real stock price in that same tool result. All values in this example are synthetic. 

{
  "response": "Your portfolio total is $180.",

  "decision": "rejected",
  "checked_field": "source.tool_0.total_value"
}

Limits and next questions

  • The verified profile is a single-operator local/private application using synthetic sample data.
  • Supported numerical and typed-field checks do not establish unrestricted natural-language entailment.
  • Live provider/model quality and browser interaction remain unmeasured.
